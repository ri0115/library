v25 — 原因特定後の修正版

今回、スクリーンショットと実HTMLを照合して2つの根本原因を確認。

原因1: object-fit の計算が逆
実CSS:
  .layer { object-fit: contain; }
v24 JS:
  Math.max(...) = cover の計算
つまり透明タップ領域を「cover画像の位置」に置いていたが、
実画像はcontain表示だった。
→ タップ座標が縦横とも実画像からずれ、頭位置でも胸部などを拾いうる。

修正:
  Math.min(...) に変更し、contain後の実画像矩形＋余白を計算。

原因2: 古い!important transformが新しいズームを上書き
旧CSS:
  .atlas.a3-zoom .layer {
    transform: translate(var(--a3x),var(--a3y)) scale(var(--a3s)) !important;
  }
v24:
  element.style.transform = translate(px...) scale(...)
CSS側!importantの方が通常inline styleより優先されるため、
v24で計算した正しいpixel transformが表示に使われていなかった。

修正:
・旧 --a3x/--a3y/--a3s transformルールを完全削除
・計算済みpixel transformを style.setProperty(...,"important") で唯一の値として設定
・transform-originは0 0に固定

承認済み境界座標は変更していない。
頭 405,10–620,185
首 405,185–620,275
胸部 340,275–680,410
腹部 350,410–675,675
骨盤 335,675–690,810
上肢/下肢も承認済み値を維持。

検証:
・JS syntax: OK
・cover計算が残っていない: OK
・旧a3変数transformが残っていない: OK
・pixel transform強制適用: OK
・?debug=1 で実タップ領域可視化
・consoleで a3SelfCheck() を実行可能
